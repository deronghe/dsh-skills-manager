# 安装、验证与发布

更新时间：2026-09-02（Asia/Shanghai）

## 安装

当前发布版本：[`@deronghe/dsh-skills-manager@0.2.0`](https://www.npmjs.com/package/@deronghe/dsh-skills-manager)。推荐直接安装，无需下载源码：

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
dsh plugin --profile web add @deronghe/dsh-skills-manager
```

重启 DSH 后在「设置 → 技能」确认插件界面已更新。若仍显示旧界面，先确认活动 profile 已重新加载该包。若下载镜像尚未同步最新包，可在安装命令末尾添加 `--registry=https://registry.npmjs.org/`。

本地开发或未发布版本可在插件根目录执行 `dsh plugin --profile web add .`。

## 发布新版本

维护者只需在插件根目录执行一键发布脚本（需先设置 `GITHUB_TOKEN` 环境变量，用于推送鉴权）：

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
$env:GITHUB_TOKEN = "你的令牌"   # 或已通过 setx 持久化
node scripts\release.mjs            # 默认 minor：0.2.0 -> 0.3.0
node scripts\release.mjs patch      # 0.3.0 -> 0.3.1
node scripts\release.mjs major      # 0.3.0 -> 1.0.0
```

脚本依次完成：校验工作区干净且位于 `main` → 升级 `package.json` 版本 → 提交 `chore(release): vX.Y.Z` → 打 `vX.Y.Z` 标签 → 推送 `main` 与标签（schannel 握手失败时自动退回 HTTP/1.1 重试）→ 尝试创建 GitHub Release（变更日志取上一标签以来的提交）。

两个 GitHub Actions 工作流都在推送 `v*` 标签时触发：

- `.github\workflows\publish.yml`：先运行 `npm test`，再通过 npm Trusted Publishing（OIDC）发布到官方 npm registry，无需保存 npm 写入令牌。
- `.github\workflows\release.yml`：用 Actions 内置令牌创建 GitHub Release（`gh release create --generate-notes`），已存在时跳过。

首次启用前，需在 npm 包设置的「Trusted Publisher」中绑定 `deronghe/dsh-skills-manager` 和工作流文件 `publish.yml`。若自动发布故障，可在完成本机身份验证后执行 `npm publish` 作为人工回退。

包内 `publishConfig.registry` 会强制指向官方 npm registry。发布后，重新执行安装命令即可获取指定版本；回滚时安装已验证版本号，例如 `dsh plugin --profile web add @deronghe/dsh-skills-manager@0.2.0`。发布脚本的 Release 创建依赖令牌的 API 权限；无 API 权限的令牌（如仅用于 git 的 fine-grained token）会自动跳过并提示，由 `release.yml` 工作流兜底创建。


## 端到端验收

1. DSH 分组与公共 Agent 分组均可见。
2. 仅 DSH 分组能启用和停用技能；公共 Agent 分组没有修改按钮。
3. 可向 DSH 分组上传 `SKILL.md` 所在目录；同名时需要确认覆盖。
4. 仅 DSH 分组可删除，公共 Agent 分组不出现删除入口。
5. 按 ESC 时只关闭最上层确认框或上传框。
6. 在 DSH Desktop（win32）中，可通过「选择本地文件」上传单个 `SKILL.md`，或通过「选择插件文件夹」打开系统原生目录选择框导入整个插件目录。

## 回滚

从 DSH Web profile 移除当前插件或恢复上一个已验证版本，然后重启 DSH。插件不会修改公共 Agent 目录中的文件结构；DSH 根目录内被覆盖或删除的技能需由安装前备份恢复。
